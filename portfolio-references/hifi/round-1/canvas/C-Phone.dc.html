iZone rebuild

I led a team of three

Row locking for enrolment

Client

Sunway University, via AvePoint

The problem

The old portal crashed at every enrolment peak. It counted submissions before they were committed, which breaks when many people submit at once. The interface was old too, and the client wanted it modernised.

The choice

Row locking (SELECT FOR UPDATE on Aurora PostgreSQL) for enrolment. I also kept the old database structure as a local replica.

What it cost

The replica wasn’t well optimised. The team was small, so I wrote code as well as leading, and that stretched me.

What happened

It’s live, but not in use yet. It was load-tested with 40,000 enrolments over 20 minutes.

Result

40,000

enrolments in a 20-minute load test

My part

Senior Technical Lead. I owned the architecture and worked with two developers, one junior and one mid-level.

Tools

OutSystems ODC, Aurora PostgreSQL, Microsoft single sign-on, private gateway

Digital Form

Just me: lead, product owner and developer

Question types added one MVP at a time

Client

Maybank

The problem

Maybank had no internal form platform. A vendor built the forms, and nothing confidential could go in them.

The choice

Question types built to be extended, so each MVP added new types and features and made the platform more stable.

What it cost

Each new question type added complexity.

What happened

Used across Maybank. By the fifth MVP it had over 80 forms, with thousands of submissions and users.

Result

80+

forms by the fifth MVP

My part
